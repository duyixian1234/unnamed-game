# Seeded determinism: one managed RNG, explicit ordering

Runs are reproducible: the game accepts a **Seed** (CLI arg / env var; a random seed is generated and logged at startup when absent), and identical Seeds produce identical Runs. All randomness is drawn from a single `GlobalRng` resource (`ChaCha8Rng`) instead of per-call `rand::rng()`; tests inject the seed as a resource directly. Because Bevy's multithreaded scheduler does not guarantee execution order of unordered systems, the project follows a discipline: **any system that consumes RNG must have explicit ordering** (same convention as the existing `CombatSet`), and integration tests additionally run the scheduler single-threaded with a fixed 60 Hz timestep as a second guarantee. Per-domain RNG streams (spawn stream, drop stream, …) were considered and rejected as premature; a single stream plus the ordering rule is simpler and sufficient. The alternative — leaving production RNG non-deterministic and only faking it in tests — was rejected because determinism is then unverifiable in the real build. Violating the ordering rule silently breaks replayability, so this ADR exists to make the rule discoverable.
