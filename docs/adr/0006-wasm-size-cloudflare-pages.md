# Wasm size optimization & Cloudflare Pages deployment

The game is deployed to **Cloudflare Pages** as a static Trunk build, which imposes a **25 MiB per-file limit** on the served wasm bundle. Meeting that constraint drove a size-focused wasm pipeline: the Bevy feature set is trimmed to only what a 2D sprite game needs (no 3D/PBR/gltf/animation/scene/mesh/gizmos/picking), dropping the release wasm from about 94 MiB to about 59 MiB; a dedicated release profile adds fat LTO and symbol stripping; and `wasm-opt -Oz` runs at deploy time for the final squeeze. The rule of thumb is **opt in to features, not out**: new Bevy capabilities must be added explicitly to `Cargo.toml` rather than relying on default features, so the bundle stays small by construction. WebGPU remains the render backend (see ADR 0001) — it was not traded away for size. The accepted cost is longer release compile times and the discipline of re-adding features when gameplay needs them, judged worth it because bundle size is a hard deployment gate, not an optimization.
